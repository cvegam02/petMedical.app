3 Enfoques para Unificar los Listados

Mismos tokens de diseño en los tres. La diferencia está en cuánta estructura se comparte.

A

Un sistema, 3 plantillas

Cada familia tiene su propia plantilla, pero todas comparten el mismo sistema de tokens: colores, tipografía, avatar size (36px), skeleton, empty state, hover. La diferencia es estructural, no visual.

B

Dos plantillas: "Con estado" y "Directorio"

Operacional y Agenda se fusionan en una sola plantilla "con estado" que maneja tanto cards activos como agrupación por fecha. Directorio queda aparte. Menos plantillas, algo más rígido contextualmente.

C

Una sola fila universal, todo en el mismo componente

Un componente DataRow único con props opcionales para el badge, fecha, estado, etc. Todos los listados usan exactamente el mismo row. La diferencia es solo en los datos que se pasan.

Ventajas

  • Un solo componente a mantener
  • Máxima consistencia visual en toda la app

Trade-offs

  • Las filas de directorio y servicios tienen necesidades muy distintas — el componente universal se vuelve genérico y pierde legibilidad
  • Las columnas fijas no encajan bien para Dueños (que muestra mascotas vinculadas) ni para Mascotas (que muestra especie/raza)

¿Por qué recomiendo A?

Las 3 familias tienen necesidades UX genuinamente distintas. Forzarlas en una sola plantilla (C) o en dos (B) produce componentes que hacen demasiado o filas que se sienten forzadas para alguna familia. Con A, cada plantilla hace exactamente lo que necesita — y el sistema de diseño es lo que las une visualmente.
